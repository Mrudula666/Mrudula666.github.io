Case studies

Problems I owned
Home Depot · Concurrency

No duplicate bulk orders, even on retry

Problem
Contractors submit large multi-line orders from several channels. Network retries and double-clicks could create the same order twice and over-reserve stock.
Approach
Idempotency keys enforced in PostgreSQL, with the order header and line-level reservation state written before any downstream call. Camunda then orchestrated split fulfilment.
Result
Retries became safe, and reservations stayed consistent across concurrent bulk orders.
Cardinal Health · AI

Semantic order search with Claude

Problem
Customers lost time finding orders with exact-match search fields.
Approach
Order and product data embedded in Elasticsearch, with Claude via Spring AI interpreting natural-language queries and ranking results.
Result
Faster order lookup, with every AI-assisted answer audit-logged for a HIPAA-regulated environment.
Cardinal Health · Data architecture

One store per access pattern

Problem
A single database couldn't serve transactions, high-volume audit logs, archives and fast lookups efficiently as volume grew.
Approach
MySQL for transactions, DynamoDB for audit records, S3 for archives, Redis cache-aside with TTL for pricing and inventory, Elasticsearch for search.
Result
Lower database load on the hot paths, with each workload on storage built for it.
TransUnion · Event-driven

Fraud and OTP events that never get lost

Problem
Identity checks, OTP delivery and fraud alerts were tightly coupled, so one slow dependency held up the rest.
Approach
Kafka topics per event type, idempotent consumers, retries and dead-letter topics, with Amazon SNS for time-sensitive customer notifications.
Result
Verification stayed responsive, and failed messages were isolated for reprocessing instead of blocking the flow.
Home Depot · Production incident

P1: production pointing at a lower-environment secret

Problem
A Kubernetes deployment referenced a lower-environment AWS Secrets Manager path, so customer-data endpoints resolved incorrectly in production.
Approach
Traced it through pod configuration and environment-specific properties, corrected the deployment config and secret reference, validated connectivity and coordinated recovery.
Result
Service restored, and new deployment checks now stop cross-environment configuration from reaching production.
